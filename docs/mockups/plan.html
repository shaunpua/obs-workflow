POC plan v2 · clinics first

Revenue Observability: proof of concept

Track every customer conversation and booking for a clinic, from any source. Measure how fast staff reply, label each lead hot, warm or cold, recognise returning patients, show where leads drop off, and tell staff what to do next.

07Leads: contacts, journeys and returning patients

A lead database has two levels. A contact is a person. A journey is one attempt to buy. Stage, temperature and next action belong to the journey, so a returning patient doesn't mess up the funnel.

  CONTACT ||--o{ JOURNEY : "buys through"
  JOURNEY ||--o{ MESSAGE : contains
  JOURNEY ||--o{ EVENT : "trace of"

    string name

  }
  IDENTITY {

  }
  JOURNEY {

    string temperature
    string outcome

Rules for returning patients

  1. Same chat id = same person. A Messenger id stays fixed for that person on that Page, so a message a year later finds the same contact.
  2. Other channels: merge automatically only on exact phone or email. Similar names become a suggestion for staff.
  3. New journey if the last one was won or lost, or the last message was more than 45 days ago (clinic default).
  4. The new journey is tagged ↺ returning and shows past visits and lifetime value.
def journey_for(contact, msg_time, cfg):
    j = latest_journey(contact)
    if (j is None or j.outcome in ("won", "lost")
            or (msg_time - j.last_activity).days
               > cfg["new_journey_after_days"]):
        return open_journey(
            contact,
            number=(j.number + 1 if j else 1),
            returning=j is not None)
    return j

09Custom per-client logic

Use the lowest level that solves the request. Never run a client's code inside your server.

3Inbound events APITheir POS or payment system calls your URL: "paid ₱12,000"their dev or n8n
4Outbound webhooksYou call their URL on hot lead, stage change, wontheir dev

6AdapterNative integration with their booking or clinic systemyou · days

12WhatsApp and Viber

WhatsApp

  • Coexistence (recommended for clinics): staff keep the WhatsApp Business phone app. You get patient messages, smb_message_echoes for phone replies, and a one-time history of up to ~6 months. Onboard through Embedded Signup or a provider such as 360dialog.
  • Cloud API only: every reply goes through your tool, so you see everything, but the number leaves the phone app.
  • Personal WhatsApp: not trackable.
  • Free replies within 24h of the patient's last message. After that only paid, pre-approved templates.

Viber

  • Viber bot (REST API): patient messages arrive by webhook, but staff replies are only seen if they reply through your tool. There's no echo from a phone.
  • Cost: bots created since 5 Feb 2024 pay a monthly fee (Viber lists EUR 100–115 per bot) plus bot-initiated messages. Messages within a 24h session the user starts are free.
  • Business Messages: phone-number messaging through Viber partners, mainly for reminders.
  • Recommendation: skip Viber until a clinic pays for it.

16LLM council review

Simulated advisor perspectives used to stress-test the plan. They are not real people.

Clinic ownerStop losing night inquiries and show me which ads bring patients. Don't make my staff learn a new inbox. The queue on a phone matters more than charts. Show me returning patients, since rebooking is my profit.→ Mobile-first action queue and returning-patient view in v1. Keep the Meta inbox.
Meta platform engineerEchoes and referrals are solid. Don't promise full Messenger history, because it's 20 messages per chat. Verification gates every Page that isn't yours, so start now. Pin a Graph API version.→ Backfill means contacts plus context. Verification is on the critical path.
Data engineerSplit contacts from journeys before real data arrives, or returning patients will distort the funnel. Keep events append-only and every metric a view. Put the client id and row-level security in from the first client.→ The schema split is the first coding task after this plan.
Product designerFour views, four jobs. Use the same chips and stage names everywhere. Charts go in the digest and owner view, not on the front desk's screen.→ Build the portal around the queue. Metabase is for owners only.
Privacy counselBackfilling months of health chats is a big step. Get consent wording, keep only what you need, and set retention. Decision hooks send patient data to other URLs and need contracts.→ Retention policy and DPA before the first backfill.
Agency operatorCustom requests kill margins. Sell config plus the events API as standard, and price adapters and hooks as add-ons. Skip Viber until someone pays.→ Packages: Standard, Plus, Custom.

Agreement: start with Messenger and Instagram on your own Page, split contacts and journeys early, build the action queue first, start verification early, and leave Viber for later. Disagreement: the owner wants the AI responder soon, while the engineer and counsel want stable measurement first. The middle path is the AI responder in phase 2, after two weeks of clean baseline data.
